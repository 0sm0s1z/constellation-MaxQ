## Policy (`maxq-open-site`, `MAXQ_BROWSER=auto`)

| Mode | Behavior |
|------|----------|
| `auto` (default) | **Camoufox primary for all sites** (AI + Discord + settings + …), not AI-only |
| `chrome` / `chromium` | Force box-chrome |
| `camoufox` / `firefox` | Force Camoufox |
| auto + Camoufox binary **missing** | **AI / Turnstile sites: fail clearly** (no silent Chrome fallback). Non-AI may fall back to box-chrome if present. |

Dry-run reason strings: `camoufox-primary-no-gpu` / `camoufox-primary` / `camoufox-missing-fallback` / `MAXQ_BROWSER=…`.

Proven on this box (no `/dev/dri`):

```

MAXQ_OPEN_SITE_DRY_RUN=1 MAXQ_BROWSER=auto maxq-open-site settings → browser=camoufox
MAXQ_OPEN_SITE_DRY_RUN=1 MAXQ_BROWSER=chrome maxq-open-site discord → browser=chrome
```

## Per-DISPLAY / onDesktopCreation

```bash
# Full theme+wallpaper+docks for one display:
DISPLAY=:<n> maxq-desktop apply

# Cheap dock-only sync (Camoufox primary, strip chrome) across all dockN:
maxq-desktop sync-displays
```

**Seam:** sand/box `onDesktopCreation` (or MaxQ API after `POST /desktops/ensure-viewers`) should call `DISPLAY=:<n> maxq-desktop apply` once, or at least `maxq-desktop sync-displays`, so every new Xvfb/agent desk gets Camoufox on Plank and loses chrome.dockitem. Without this hook, apply on `:23` alone leaves `:1` (Matthew’s view) stale.
